# 给脚本作者：让管家把你的脚本跑稳

管家能挂三类脚本：MaaFramework 项目（有 `interface.json` 的文件夹）、BetterGI / 三月七 / 明日方舟 MAA、任意命令行程序（.exe / .bat / .py）。挂上就能跑；下面这些是让它「跑得稳、判得准」的办法。

## 1. 告诉管家结果：脚本信号

在日志或 MaaFramework 的提示文字（focus）里输出下面任意一行，管家就按它记结果。不输出也能用，管家会按框架结果和成败判定来判。

| 信号 | 意思 | 管家怎么做 |
| --- | --- | --- |
| `[GB_DONE] 任务名` | 这一项确认完成 | 记完成 |
| `[GB_FAIL] 任务名 原因` | 失败 | 按重试规则处理，最后记失败 |
| `[GB_MANUAL] 原因` | 要人工处理（验证码、扫码） | 这个游戏后面的任务不跑，推送提醒 |
| `[GB_PAUSE] 原因` | 脚本自己暂停（例如发现有人在用电脑） | 记「已停止」，之后照常再跑 |
| `[GB_FUSE] 原因` | 熔断（例如剑三误入 PvP） | 立刻停掉整次运行，推送，当天不再自动跑这个游戏 |

信号比所有判定规则都优先；熔断只认信号。

## 2. 预设：挂载时自动套用的运行设置

`config/presets/<名字>.json`。挂载时按 interface 名称、GitHub 地址或程序文件名认出是哪个脚本，把 `config` 里的设置写进游戏记录。

**管家不带默认任务清单**：预设里不写要跑哪些任务。Routine 一开始是空的；脚本自己在 `interface.json` 里写了 `preset`，或用户在 MFA 里存过配置，挂载时会问用户要不要一同导入。

```json
{
 "id": "maash", "name": "MaaSH（时绘 MAA）", "game": "时空中的绘旅人",
 "type": "maa", "kind": "MaaFramework 项目", "repo": "LiliiPop/MaaSH",
 "match": {"names": ["MaaSH"]},
 "config": {
  "refresh": "05:00",
  "package": "com.netease.skzdhlr",
  "recovery_task": "✈️启动绘旅人",
  "before_startup": ["📰读游戏内公告"],
  "always_last": ["🏁结束后操作", "💤关闭绘旅人"],
  "timeouts": {"default": 5, "stall_minutes": 3, "retries": 1, "✈️启动绘旅人": 12},
  "judge": {"fail": {"*": ["公共_任务失败", "启动_超时"]}, "success": {"📅签到": ["Flag_签到完成"]}}
 }
}
```

`config` 里能写的字段，游戏页「高级」里都能看到、改到：

| 字段 | 意思 |
| --- | --- |
| `recovery_task` | 启动任务：有任务要跑时放最前；卡住时用它重新进游戏 |
| `before_startup` | 排在启动任务前面的任务（在登录页做的） |
| `run_order` / `always_last` | 固定先后 / 总放最后 |
| `judge` | 成败判定（见下一节） |
| `timeouts` | `default` 每个任务最长几分钟、`stall_minutes` 几分钟画面没变化算卡住、`retries` 重试几次，再加「任务名: 分钟」 |
| `task_retries` | {任务名: 次数}，单独覆盖重试次数 |
| `retry_on_fail` / `restart_on_fail` | 报失败也重试 / 重试前先重启游戏 |
| `back_presses` | 卡住后先按几次返回键 |
| `windows` | {任务名: "12:00-15:00"}，只在这个北京时间段跑 |

## 3. 成败判定（MaaFramework 项目）

框架说「成功」不一定真的做成了。`judge` 只有两类：

- `fail`：命中就判失败（即使框架报成功）。
- `success`：命中就判完成。写在某个任务下的默认是「必须命中」：一个都没命中、框架却报成功 → 判失败（流程走完了但没做成）。不想这样写 `{"match": "…", "required": false}`。

条目可以是识别节点名，或提示文字里出现的字。还没判成完成的：命中标了 `"result": "exhausted"` 的算「完成（无可做）」，例如次数用完；写了 `{"verify": "节点名"}` 的，管家会跑这个节点核对画面，通过也算「完成（无可做）」。

键 `"*"` 对这个游戏的所有任务生效，其他键是任务名。

## 4. 识别补丁：不改你的项目文件

管家不修改 MAA 项目里的任何文件。识别模板要补的，放在管家文件夹的 `overlays/<游戏>/` 里，管家运行时叠加上去。

## 5. 命令行脚本

挂载时填几条命令（一条命令 = 一个任务）、参数、最长运行时间、成功标志（日志里出现的字）。没写成功标志的，程序退出码 0 就算完成。脚本里输出第 1 节的信号，管家会照着记。
